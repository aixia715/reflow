# Reflow 前端风格指南

> **改任何前端文件（`app/templates/`、`app/static/`）之前必读。**
> 目标：风格一致、两套主题都好看、交互符合本工具已有的习惯。改完务必对照文末自检清单。

## 设计原则

- 视觉基调对齐 GitHub：浅灰底、白色卡片、细边框、小圆角、13–14px 字号。克制，不花哨。
- 信息密度优先：这是工程师每天用的工具，不是营销页。少留白堆叠，多用紧凑的 panel/badge/chip。
- 桌面单栏布局，`main` 最大宽度 1100px，居中。移动端适配集中在 `style.css` 末尾「移动端适配」分区：单断点 `@media (max-width:720px)` 管窄屏布局，`@media (hover:none)` 管触屏（悬停按钮常显、点按区加大）；只写追加覆盖，不改桌面样式，不做多级断点。

## 设计令牌（最重要的一条规则）

所有颜色**只允许用 `style.css` 顶部 `:root` 里的 CSS 变量**，禁止在模板或新样式里写裸色值（`#xxx`、`rgb()`）。唯一例外是 `rgba()` 阴影和半透明边框（如 `#cf222e66`）。

- 夜间模式实现方式：`[data-theme="dark"]` 块**只覆盖颜色变量**，不写任何结构样式。
- **新增一个颜色变量，必须同时在 `[data-theme="dark"]` 块里给出夜间值**，否则夜间模式会破。
- 语义变量速查：
  - 底色/文字：`--bg` 页面底、`--surface` 卡片、`--surface-2` 次级面、`--fg` 正文、`--muted` 次要文字
  - 边框：`--border` 常规、`--border-soft` 表格行/分隔线
  - 语义色：蓝=链接/选中/进行中，绿=主操作/新增，红=危险/删除，黄=警告/修改，紫=根节点/特殊
  - 每个语义色有前景（`--blue`）和浅底（`--blue-bg`）成对出现，badge/flash/高亮行成对使用
- 圆角统一 `var(--radius)`（6px），药丸形（badge/chip）用 `999px`。

## 组件清单（先复用，再新建）

写新界面前先翻 `style.css`，下面这些已有组件覆盖了绝大多数需求：

| 类 | 用途 |
|---|---|
| `.panel` / `.panel-title` | 白底卡片容器；侧栏、表单、分组都用它 |
| `.badge` `.badge-{blue,green,yellow,red,purple}` | 状态标签（已提交/未提交/数量） |
| `.chip` / `.chip.pending` | 可点击的药丸链接（单板入口） |
| `.btn` / `.btn-primary`（绿实心，每页至多一个）/ `.btn-outline`（`.danger` 红边框+红字）/ `.btn-link`（`.danger` 红） | 按钮层级；非表单元素（如 `<a class="btn">`）用 `.disabled` 类做伪禁用态（`opacity:.5` + `pointer-events:none`），配合 `aria-disabled`/`tabindex="-1"` |
| `.input` / `label` | 表单控件，13px |
| `.flash` `.flash-{error,warn,info}` | 页面内提示条 |
| `.problem-list` | `.flash` 提示条下方的逐条明细列表（位号校验问题、CSV lint 提示等），配合 `<code>` 标注位号 |
| `.lint-warn` / `.lint-fix` | 只负责 `.lint-note` 的配色（黄 ⚠ / 蓝 ⓘ），单独使用无意义——行内提示的完整用法见下面的 `.lint-note` 条目。整屏/整批的问题仍用 `.flash` + `.problem-list` |
| `.toast`（经 `showToast()`） | 操作成功的瞬时反馈 |
| `.modal-overlay` / `.modal` / `.modal-head` / `.modal-foot` | 弹窗（目前仅冲突确认） |
| `.empty` | 虚线框空状态，必须带引导文案 |
| `.icon-btn`（`.danger` 红 / `.hover-only` 配合表格） | 内联 SVG 图标按钮（笔=回填编辑、撤销=箭头、垃圾桶=删除附件）：色随 `currentColor`、默认 `--muted`，hover 变蓝、`.danger` 变红；务必带 `title`+`aria-label` |
| `.ico` / `.row-icons` | 15px 线性图标本体（`stroke:currentColor`）/ 行内图标按钮组横向容器 |
| `.lint-note`（配 `.lint-fix` 蓝 ⓘ / `.lint-warn` 黄 ⚠） | 挂在修改行末尾的行内提示图标：ⓘ=元器件值已自动修正、⚠=需人工判断的警告。提示合并进行内，不再单列清单段落。内部 `.ico` 收窄到 13px（行内紧凑尺寸），与独立按钮里的 15px `.ico` 有意不同。**提示文案放 `data-tip`（不是 `title`）**，并带 `tabindex="0"` `role="img"` `aria-label`；气泡、`cursor:help` 与放大到 21×19 的命中区都只挂在 `.lint-note[data-tip]` 上——漏传 `data-tip` 时 `attr()` 取到空串会弹出一个只有 padding 的空气泡，且没有定位祖先时会跑到视口右下角，故用属性选择器兜底。气泡靠 `.change-row` 的 `position:relative` 定位，右对齐到**行**右缘（对齐到图标的话，图标靠左时会顶出屏幕）。**ⓘ 是一次性的**：值在写入前已归一，原始写法不留存，页面一刷新重算就只剩 warning 级，ⓘ 随之消失——这是「修改」面板里唯一不刷新后仍保留的提示，别把它当成持久状态来用 |

| `table.bom` + `tr.row-{add,modify,remove}` | BOM 表格及差异行底色 |
| `.table-scroll` | 表格横向滚动容器；所有 `table.bom` 外层必须套它，防窄屏页面横滚 |
| `.timeline` / `.tl-item` / `.tl-card` | 状态图节点链；对比模式下硬更改用 `.tl-item.hard.disabled` 置灰且禁用交互 |

新建组件的条件：现有组件确实不能组合出来。新类写进 `style.css` 对应区块附近（文件按「全局 → 组件 → 页面特有 → 弹窗/toast → 夜间」分区），命名跟随现有风格（短横线小写、语义命名）。**不引入任何 CSS 框架、不加构建步骤、不写内联 style。**

## 页面骨架

- 一律 `{% extends "base.html" %}`，填四个 block：`title`（格式「页面 — Reflow」）、`crumbs`（面包屑，首页开头）、`ctxlinks`（header ⋯ 菜单里的功能入口；内容会被拍平成纵向菜单项，danger 类保持红色）、`content`。
- 局部模板（HTMX swap 用）以 `_` 开头，不 extends。
- 页面顶部用 `.page-head`：`h1`（18px）+ 状态 badge + 右侧 `.stable-link` 等。

## 交互模式（HTMX + Alpine 惯用法）

整体约定见 CLAUDE.md「前端约定」一节，此处是落地细节：

- **局部刷新优先**：编辑、撤销、删除走 HTMX；只有创建/跳转类操作整页跳转（用 `?flash=` 带 toast 文案）。
- **校验失败**：后端返回 200 + `HX-Retarget: #form-error`，错误就地显示在表单旁，不弹窗、不跳页。
- **操作成功**：`HX-Trigger: {"showToast": "…"}` 给瞬时反馈；toast 3.5s 自动消失，不需要用户点掉。
- **危险操作**三件套，缺一不可：
  1. 入口低调——`.icon-btn.danger`（图标）或红色 `.btn-link.danger`，绝不用大红实心按钮常驻页面；
  2. `hx-confirm` 确认，文案格式固定：`确认删除「对象名」？此操作将…，不可恢复。`（写明波及范围）；
  3. 完成后 toast 或 flash 告知结果。
- **悬停渐显**：表格行内操作按钮加 `.hover-only`，避免视觉噪音。
- **纯客户端页面（插入节点页）的三处等价写法**：该页改动只暂存在浏览器、没有落库请求可挂响应头，所以上面几条要换个写法实现，观感必须一致——
  1. 危险操作的第 2 件套用原生 `confirm()` 代替 `hx-confirm`（htmx 用的就是 `window.confirm`），文案格式照旧；
  2. toast 自己往 body 派 `showToast`（`document.body.dispatchEvent(new CustomEvent('showToast', {detail: {value: msg}}))`），形状与 `HX-Trigger` 派的一致；
  3. 离开前有暂存改动要挂 `beforeunload` 守卫，并在保存请求开始时用 `saving` 解除（HX-Redirect 也是一次 unload，不解除就会「存成功了还问你要不要离开」，用户选「留下」时节点已经建好，再点一次会重复插入）。
- **非 htmx 的整页 POST 表单，提交前确认用 `@submit` 守卫 + 原生 `confirm()`**：`hx-confirm` 只对 htmx 请求生效，普通 `<form method="post">` 上挂了也不会弹。写成 `@submit="if (!check()) $event.preventDefault()"`，判断逻辑默认放宿主 `x-data` 的方法里（示例见 `hard_change_form.html` 的 `compressing` 守卫）；「取消」等价于什么都不做，并把用户送回需要他动手的地方（滚过去 + `focus()`，只滚不移焦点的话键盘用户还得自己 Tab 回来）。注意这跟下面「插入节点页用原生 confirm」是两回事：那条的理由是页面不落库，这条的理由是表单不走 htmx。
  - **同一个守卫要被 `x-data` 作用域外的表单复用时，写成页面级函数 + `onsubmit="return check()"`**：htmx 换进 `base.html` 那个 `#modal` 的弹窗（如 `_conflict_modal.html`）不在页面 `x-data` 里，够不着组件方法。把函数提到 `<script>` 顶层，页内表单继续用 `@submit`，弹窗用 `onsubmit` 返回布尔值。示例见 `node_detail.html` 的 `confirmPendingAttachments()`（附件已选未上传时拦一道）——它就是上一条「放 `x-data` 方法里」的例外。这类守卫的「送回原地」还要判一下遮罩：`#modal .modal-overlay` 在时附件面板压在弹窗底下，滚过去看不见、焦点也是隐形的，此时什么都别做。
  - **走 htmx 的按钮没有 submit 事件可拦，用 `htmx:confirm`**：`hx-confirm` 是无条件弹，想按情况决定弹不弹就监听 `@htmx:confirm`（htmx 1.9 起对每个请求都发，与有没有 `hx-confirm` 无关）：`$event.preventDefault()` 先掐掉请求，条件满足再 `$event.detail.issueRequest()`。事件会冒泡，务必用 `$event.target === $el` 圈定是自己这颗按钮。示例见 `node_detail.html` 的「📥 添加到草稿」（`HX-Redirect` 一跳，已选未上传的附件就没了）。
- **「输入即请求」类端点必须挂失败兜底**：返回 204 + `HX-Trigger` 的校验/联想请求，失败时 htmx 收不到触发器、回调根本不跑，而全站没有 htmx 错误兜底（base.html 只挂了 `htmx:afterSwap`）——按钮点下去毫无反应，用户只会以为没点上。给触发元素挂 `@htmx:response-error.camel` / `@htmx:send-error.camel` 写进就地错误位（示例见 `insert_node.html` 的「添加这条」）。
- **回执迟到不许抹掉用户新敲的内容**：请求飞在路上时用户可能已经在输入下一条，回调里清空输入框/抢焦点前要比对「提交那一刻的快照」，三项（位号、op、Part）全等才清——只比位号会漏掉「同一位号改 Part」那一路。
- **表单级 `hx-trigger="change"` 要防误触发**：挂在 `<form>` 上的 change 会被表单里**任何**控件的变化触发，包括分段控件（`.seg`）的 radio。若某些变化本不该发请求（例：导入面板还没选 CSV 文件就切换「差异 / 全量」，会发一次注定失败的请求、回一句「请选择 CSV 文件」打断用户），把条件写进触发器本身：`hx-trigger="change[importHasFile()]"`。
  - **过滤函数必须返回严格布尔 `true`**：vendored htmx 1.9.12 的判定是 `filter.call(elt, evt) !== true` 即取消事件，返回 `input.files.length` 这类 truthy 非 true 的值会把**所有**请求都静默屏蔽掉。写 `return !!(…)`。
  - 函数按 id 查 DOM、不依赖过滤器里的 `this`（htmx 内部绑定语义不必依赖）。现存示例见 `importHasFile()`。
- **CSV 导入面板是两页共用的**：节点页（工作区草稿）与插入节点页都用 `#import-form` + `#import-preview` + `_import_preview.html`，配套的 `importHasFile` / `cancelImport` / `importRequestFailed` 放在 `app/static/csv_import_panel.js`——曾各自抄过一份，改一处漏一处。预览片段的「应用」是双模式：工作区落库走 `hx-post`，插入页 `client_apply=True` 时改为把服务端换算好的清单合进浏览器暂存（那一页本就不落库）。两页的导入表单都要挂 `@htmx:response-error.camel` / `@htmx:send-error.camel`：返回的是 HTML 片段，失败时 htmx 什么都不换，指示条一消失、预览区空着，用户只会以为没反应。
- Alpine 监听 htmx 事件加 `.camel` 修饰符；模板向 `hx-vals`/JS 传值一律 `|tojson` 且 HTML 属性用单引号。
- 弹窗挂载点是 base.html 的 `#modal`；取消必须等价于「什么都不做」的安全选项。
- **弹出菜单的关闭机制**：菜单按钮若带 `@click.stop` 或 `stopPropagation()`（阻止冒泡），就**不能**用 `@click.outside` 关闭——它依赖事件冒泡，会被 stop 拦截，导致点别处时菜单不消失。这种情况用 `@close-menus.window="if (!$el.contains($event.detail)) open=false"`：base.html 在**捕获阶段**对任意点击广播 `close-menus`（先于按钮的 stop 执行），菜单据此判断点击是否落在自身之外来决定关闭（见 `state_graph.html`）。按钮不带 stop 的简单菜单仍可用 `@click.outside`。
- **ESC 分层退出**：菜单自己用 `@keydown.escape.window="open=false"` 关闭，并挂 `:class="{ 'menu-open': open }"` 声明「我展开着」。页面级 ESC 行为（如状态图退出对比）要让菜单先吃掉这一下按键，判据是 base.html 在捕获阶段打在事件上的 `$event.menuWasOpen`——**不要在自己的处理器里现查 DOM**：Alpine 各 `.window` 监听器之间会穿插微任务刷新，别的菜单可能已经把类摘掉了。

## 文案（人性化的主要载体）

- 全部中文，语气直接、信息完整：说清**发生了什么、影响范围、下一步**。
  - 好：「⚠ 这是已提交的历史节点。在此编辑＝**修正历史记录**，会自动向下游传播。」
  - 差：「警告：操作有风险。」
- 空状态必须给出第一步引导（参考首页 `.empty`：「点右上角『＋ 新建单板』上传初始 BOM CSV 开始。」）。
- 图标按钮必须有 `title` 提示。**但「需要被读到」的解释性文案不要用 `title`**：原生 tooltip 要停悬约 1 秒才出、几秒后自动消失、且不移出元素就不再复现，扫视列表时基本等于不出现。这类提示走 `data-tip` + CSS `::after` 气泡（见 `.lint-note`），并给元素 `tabindex="0"` 让键盘/触屏也能唤出；`title` 与气泡不要并存，否则叠出两个。
- 数字信息用 `·` 分隔的紧凑写法：`12 个位号 · 3 块单板`。
- 错误消息也是中文（前后端一致）。
